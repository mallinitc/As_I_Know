ARCA HACKATHON DEMONSTRATION — VERIFIED CASES
================================================

Environment
-----------
Run ARCA in mock mode and choose Azure Environment unless a case explicitly says AWS.
Every “Verified demo example” dropdown is optional; selecting Manual entry preserves normal entry.
The examples populate inputs but never submit, approve, execute, or change source evidence.

1. STAGE 1 — VALIDATE CHANGE
----------------------------
Navigation: Change Lifecycle > Stage 1 — Validate Change.
Select an example, review the populated pasted record, then click Validate draft.

S1-VALID — Complete storage configuration draft
Expected: VALID / Ready for Submission. Problem: none. Correction: none.

S1-MISSING-IMPLEMENTER — Missing implementer
Expected: INCOMPLETE. Problem: implementer is mandatory. Correction: enter the authorized UPN or principal ID.

S1-MISSING-RESOURCE — Missing target resource
Expected: INCOMPLETE. Problem: resource and expected operation are absent. Correction: enter the exact resource name/ID and operation.

S1-REVERSED-WINDOW — End time precedes start time
Expected: INCONSISTENT. Problem: 09:00Z end precedes 10:00Z start. Correction: provide a chronological UTC window.

S1-AMBIGUOUS-TASK — Ambiguous implementation instruction
Expected: AMBIGUOUS. Problem: “Update as needed” is not executable. Correction: provide ordered, resource-specific steps.

Stage 1 copy/paste success example:

6. ASK ARCA
-----------
Navigation: Ask ARCA. Select example, then click Ask ARCA. Suggested buttons and custom text use the same agent path.

ASK-PIM: “Who requested Contributor access at subscription scope this week?” => complete; matching PIM evidence.

ASK-UNSUPPORTED: weather question => unsupported; use a cloud change/access investigation question.

Evidence integrity notes
------------------------
All 41 catalog scenarios were programmatically executed against the local evaluators.
Azure historical reference: latest applicable synthetic evidence timestamp, exposed in Environment Details.
AWS historical reference: latest applicable CloudTrail timestamp, exposed in Environment Details.
No paid model or cloud API is required. No catalog action modifies the synthetic datasets.
