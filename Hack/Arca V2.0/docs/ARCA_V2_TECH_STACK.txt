ARCA V2 TECHNOLOGY STACK
Verified from the installed environments and manifests on 2026-10-22

1. High-level architecture

ARCA V2 is a native two-tier application. A Next.js App Router frontend calls
a versioned FastAPI JSON API. Backend repositories load isolated synthetic AWS,
Azure, and Snowflake JSON evidence. Provider-specific deterministic services
perform validation, access analysis, execution correlation, investigation, and
analytics. An optional HTTP LLM gateway can add advisory analysis without
altering deterministic security decisions.

4. Five-agent architecture

Agent 1 - Change Quality: mandatory-field and clarity assessment; editable
change-draft preparation can be optionally refined by the model.
Agent 2 - Access Intelligence: AWS IAM, Azure PIM/RBAC, and Snowflake role and
scope assessment using provider-specific deterministic rules.
Agent 3 - Execution Assurance: approved intent versus observed execution and
identity/activity evidence.
Agent 4 - Risk Investigation: provider-specific or cross-environment risk and
potentially undocumented activity analysis.
Agent 5 - Ask ARCA: conversational intent resolution, allowlisted read-only
tool planning, deterministic investigation, and optional evidence-grounded
advisory synthesis.

5. Execution modes and safety

Deterministic mode is the default and requires no model connection.
LLM-assisted mode supports openai, azure_openai, and openai_compatible gateway
contracts. Model output is Pydantic-validated and advisory. It cannot change
the deterministic finding status/severity, approve access, or execute a cloud
change. Provider evidence adapters and the LLM provider are independent.

6. Provider evidence adapters

AWS: data/aws/ through backend/repositories/aws.py; AWS-specific IAM/action,
scope, execution-event, and investigation behavior remains separate.
Azure: data/azure/ through backend/repositories/azure.py; Azure PIM, RBAC role
definitions/assignments, resources, and Activity Logs remain distinct.
Snowflake: data/snowflake/ through backend/repositories/snowflake.py; changes,
roles/grants, query/access/login history, objects, and scenario catalogs are
evaluated using Snowflake-specific services.

All three adapters use synthetic local evidence and make no live cloud calls.

8. Startup requirements

Backend dependencies must be installed in ARCA_V2/.venv. Port 8000 must be
available. scripts/start_api_v2.bat starts Uvicorn at 127.0.0.1:8000.
Frontend dependencies must be installed with npm ci in frontend/. Port 3000
must be available. Run npm run dev -- --hostname 127.0.0.1 --port 3000.
The API CORS allowlist must include the exact frontend origin.

9. Known external connectivity limitation

The latest controlled verification resolved api.openai.com but could not open
TCP 443 from this workstation. Deterministic operation is unaffected. A live
LLM request requires outbound HTTPS, a valid untracked API key, provider/model
access, and any organization proxy/CA settings. No AWS, Azure, or Snowflake
network connectivity is required for the synthetic demo.
